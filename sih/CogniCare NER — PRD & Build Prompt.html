Product Requirements Document

CogniCare NER — AI-Powered Cognitive Gaming & Memory Assistance Platform for Elderly Dementia Patients

Stack: MERN (MongoDB, Express.js, React, Node.js) Deployment target (Phase 1): Local / offline-first, single-machine or LAN deployment Document version: 1.0 Prepared for: SIH / Hackathon submission — North Eastern Region elderly healthcare

1. Problem Statement Summary

Elderly patients in the North Eastern Region (NER) suffer from rising rates of dementia and cognitive decline, with limited access to neurological care due to geography and thin healthcare infrastructure. Caregivers struggle with continuous monitoring. There is no affordable, culturally-relevant, multilingual digital cognitive therapy tool built for this population. CogniCare NER addresses this gap with an adaptive cognitive gaming platform that works offline, speaks regional languages, and gives caregivers visibility into patient progress.

2. Goals & Success Metrics

Goal Metric
Improve cognitive engagement Avg. sessions/week per patient ≥ 4
Adaptive difficulty works ≥70% of sessions end in "flow zone" (60–85% success rate)
Caregiver visibility Caregiver dashboard viewed ≥ 2x/week
Works offline 100% of game modules playable with zero connectivity
Elderly usability Task completion without assistance ≥ 80% in usability testing
Reminder adherence ≥70% reminders acknowledged within 30 min

3. Users & Personas

  1. Patient (Elderly, 60–85, mild-to-moderate cognitive decline) — large text/buttons, voice-first, regional language (Assamese, Bodo, Khasi, Mizo, Nepali, Manipuri, Hindi, English to start), low digital literacy.
  2. Caregiver / Family member — monitors progress remotely, sets reminders, receives alerts.
  3. Healthcare Worker / ASHA-style user — manages multiple patients, views aggregated cognitive trend dashboards, flags concerning patterns.
  4. Admin (clinic/NGO) — manages patient accounts, content, and language packs.

4. Functional Requirements (mapped to problem statement)

a. Cognitive Game Modules

  • Memory Match — card-pairing with familiar regional objects/faces
  • Daily Routine Recall — sequence-ordering of daily tasks (brushing → bathing → eating, shown as images)
  • Pattern & Object Recognition — identify odd-one-out, match shapes/regional motifs
  • Attention/Concentration — spot-the-difference, simple reaction-time tasks
  • Reminiscence/Emotional Engagement — audio-triggered "tell me about this" prompts with familiar regional imagery (tea gardens, festivals, local landmarks)

b. Adaptive Difficulty Engine (AI/ML)

  • Tracks per-game accuracy, response time, hesitation patterns, and streaks
  • Adjusts difficulty tier (Easy/Medium/Hard) per session using a rolling-performance model (rule-based + lightweight ML classifier — see Section 8)
  • Flags cognitive decline/improvement trends over time for healthcare worker review

c. Multilingual & Voice

  • UI language packs: English, Hindi, Assamese, Bodo, Khasi, Nepali, Manipuri (extensible JSON i18n structure)
  • Voice instructions via text-to-speech (offline TTS engine bundled) per language
  • Voice input for simple commands ("start game", "next", "help") using on-device speech recognition where feasible

d. Cultural Familiarity

  • Regional imagery/icon packs (configurable by admin per state/community)
  • Local festival themes, folk-pattern visuals, regional audio cues instead of generic sounds

e. Reminders

  • Medicine reminders (time + dosage + photo of pill/strip)
  • Hydration nudges (interval-based)
  • Daily activity prompts (walk, game session, meal)
  • Medical appointment reminders (date/time, synced when online)
  • All reminders queue locally and fire via local notifications even offline

f. Caregiver/Healthcare Worker Dashboard

  • Patient list with last-active, streak, and cognitive trend sparkline
  • Per-patient drill-down: game-by-game accuracy over time, reminder adherence, session duration
  • Alerts: missed medication, sudden performance drop, prolonged inactivity
  • Exportable weekly summary (PDF/CSV)

g. Offline-First / Low-Connectivity

  • All games and reminder logic run fully client-side (IndexedDB/local storage)
  • Background sync service pushes session logs to MongoDB backend when connectivity resumes
  • Conflict resolution: last-write-wins per session-ID with timestamp

h. Elderly-Friendly UI/UX

  • Large tap targets (min 64px), high-contrast themes, minimal text, icon-first navigation
  • Single-task-per-screen design, no nested menus deeper than 2 levels
  • Optional "Simple Mode" (voice + 3 buttons only) vs "Full Mode" (for tech-comfortable users/family setup)

5. Non-Functional Requirements

  • Offline-first architecture using Service Workers (PWA) + IndexedDB
  • Data privacy: patient health data encrypted at rest (AES-256) and in transit (TLS); role-based access control
  • Performance: game load time < 2s on low-end Android tablets (2GB RAM)
  • Accessibility: WCAG 2.1 AA where applicable, screen-reader-compatible labels
  • Scalability: backend designed to later scale from local/LAN to cloud (stateless Express API, MongoDB Atlas migration path)
  • Localization: all copy externalized to i18n JSON, no hardcoded strings

7. Core Data Models (MongoDB Collections)

User

{ _id, role: "patient"|"caregiver"|"healthworker"|"admin",
  name, phone, preferredLanguage, linkedPatients: [ObjectId],
  createdAt }

Patient

{ _id, userId, age, cognitiveBaseline: "mild"|"moderate"|"severe",
  currentDifficultyTier: {memory:1, attention:1, pattern:1, routine:1},
  caregiverIds: [ObjectId], region, preferredLanguage }

GameSession

{ _id, patientId, gameType, difficultyTier, startTime, endTime,
  accuracy, avgResponseTimeMs, hesitationCount, completed, syncedAt }

Reminder

{ _id, patientId, type: "medicine"|"hydration"|"activity"|"appointment",
  scheduleTime, recurrence, label, photoUrl, acknowledgedAt }

CognitiveScore (aggregated, computed nightly/on sync)

{ _id, patientId, weekOf, avgAccuracyByGame: {...}, trend: "improving"|"stable"|"declining" }

8. Adaptive Difficulty — ML Approach (Phase 1, lightweight)

Phase 1 (hackathon-feasible): rule-based adaptive engine

  • If last 3 sessions' accuracy > 85% → increase tier
  • If accuracy < 50% → decrease tier
  • If response time increasing while accuracy stable → flag possible fatigue, not decline

Phase 2 (stretch/ML upgrade): a small logistic regression / decision-tree classifier (scikit-learn, trained offline, exported to ONNX or reimplemented as simple weighted scoring in Node) using features: accuracy trend, response-time trend, hesitation rate, session frequency → predicts difficulty_adjustment and decline_risk_flag. This keeps the "AI/ML adapts difficulty" requirement genuinely model-driven without needing heavy infra.

9. MVP Scope (for hackathon/demo, local MERN)

In scope:

  • 2 game modules fully working (Memory Match + Daily Routine Recall)
  • Rule-based adaptive difficulty
  • 2 languages (English + 1 regional, e.g., Assamese) with TTS instructions
  • Medicine + hydration reminders (local notifications)
  • Caregiver dashboard: patient list + per-patient session history + trend chart
  • Offline play with sync-on-reconnect
  • JWT auth with patient/caregiver/healthworker roles

Out of scope for MVP (roadmap):

  • Full 5-language pack, voice command input, appointment sync, PDF export, ML classifier upgrade, native mobile app (React Native) — noted as Phase 2/3.

12. Build Prompt (for Claude Code / AI code generation)

Use this as the initial instruction when generating the codebase:

Build a MERN stack web application called CogniCare NER, an offline-first cognitive gaming and reminder platform for elderly dementia patients in India's North Eastern Region, following this PRD. Requirements:

  1. Set up a monorepo with /client (React + Vite, PWA-enabled via Workbox, react-i18next for i18n, Dexie.js for IndexedDB offline storage) and /server (Node.js + Express + Mongoose, JWT auth with roles: patient, caregiver, healthworker, admin).
  2. Implement the MongoDB schemas exactly as specified in Section 7 (User, Patient, GameSession, Reminder, CognitiveScore).
  3. Build two playable mini-games as React components with large, high-contrast, elderly-friendly UI: (a) Memory Match (card pairs with image assets), (b) Daily Routine Recall (drag-to-order sequence of daily activity icons). Each game must log accuracy, response time, and hesitation count locally, then sync to the backend when online.
  4. Implement the rule-based adaptive difficulty engine described in Section 8 as a reusable server-side module, exposed via an API endpoint that returns the next difficulty tier given a patient's recent session history.
  5. Add a reminders module: CRUD API for medicine/hydration/activity/appointment reminders, with local browser notifications firing from IndexedDB-cached reminder data even when offline, syncing acknowledgments when back online.
  6. Build a caregiver/healthworker dashboard (protected route) showing: patient list, per-patient session history table, an accuracy-trend line chart (use a lightweight chart library), and a reminder-adherence summary.
  7. Implement i18n with at least English and one regional language (Assamese), with all UI strings externalized to JSON language files, and add text-to-speech playback of game instructions using the Web Speech API with graceful fallback if unavailable.
  8. Implement offline-first behavior: a service worker caches the app shell and game assets; all gameplay and reminder-ack writes go to IndexedDB first and sync to MongoDB via a background sync queue when connectivity is detected.
  9. Set up local run instructions matching Section 11 — no cloud dependencies required to run and demo the app end-to-end on localhost.
  10. Keep the codebase modular and commented so game modules, language packs, and the difficulty engine can each be extended independently in later phases.

Start by scaffolding the project structure and schemas, then build the auth flow, then the two game modules, then reminders, then the caregiver dashboard, then offline/i18n/voice layers.

13. Risks & Mitigations

Risk Mitigation
Low digital literacy of elderly users Voice-first "Simple Mode", caregiver-assisted onboarding
Poor/no connectivity in remote NER areas Full offline-first architecture, background sync
Language coverage limited at MVP Extensible i18n JSON structure, community-sourced translations post-pilot
Data privacy for health info Encryption at rest/in transit, RBAC, local-first storage minimizes exposure
False difficulty/decline flags Start rule-based, validate with clinicians before enabling ML-driven alerts
